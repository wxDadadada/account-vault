# 架构与边界

## 代码分层

`src/main.tsx` 注册路由与全局提供器，`src/vault/App.tsx` 负责应用外壳。`pages/` 组织页面，`components/` 放置业务控件，`hooks/` 封装交互行为，`state/` 管理账号库状态与会话；`lib/` 包含数据模型、领域规则、加密和浏览器工具。

`server/` 提供 API 与持久化，`shared/` 保存两端共用的协议与校验。账号正文的解析、查询和加密仍在浏览器完成。完整目录及新增文件约定见 [开发与目录约定](development.md)。

## 一次保存如何工作

React 在浏览器内存中维护解锁后的账号库。每次编辑通过结构校验和业务规则，生成版本记录，然后把整个账号库加密为一个 AES-256-GCM 密文。Fastify 校验会话、来源和信封格式，通过 SQLite revision 比较后保存。版本不匹配返回 409，界面提示先同步；本次内容不会静默覆盖另一台设备的修改。

数据结构包括账号、主体、分类、历史、AI 配置和偏好。历史保存修改前后快照，删除也会留痕；恢复会增加新记录。默认每账号保留 20 条，可调整到 5–100 条。历史保留的旧密码同样属于敏感内容。

## 密钥与认证

- 首次创建时生成随机 256 位数据密钥，用于加密账号库。
- 主密码结合随机盐，经 PBKDF2-HMAC-SHA256 600,000 次派生 512 位材料，分别用于密钥包装和登录证明。
- 随机 256 位恢复密钥提供第二条数据密钥包装路径，恢复认证使用独立域标签的摘要。
- AES-GCM 每次生成随机 96 位 IV，并用不同 AAD 标签区分账号库、主密码包装和恢复包装。
- 服务端仅保存登录／恢复证明的 scrypt 哈希，随机会话令牌也只存哈希；Cookie 为 HttpOnly、SameSite=Strict，HTTPS 时为 Secure 和 `__Host-` 名称。
- 修改主密码与恢复均更新包装、替换恢复凭据并撤销所有旧会话；改密在异步哈希结束后的写入事务中再次验证原会话，撤销或过期的在途请求不能更新凭据。恢复还会关闭 TOTP。
- TOTP 使用独立服务密钥加密存储；绑定成功撤销现有会话，验证码拒绝重放。

主密码不发给服务器。账号正文没有明文 SQLite 列和服务器搜索索引。匿名登录资料仅含用户名、KDF 参数及随机 256 位恢复密钥的包装；主密码包装仅在认证（包括已开启的 TOTP）成功后返回，避免匿名调用者取得离线猜测主密码的验证材料。便携备份仍保留完整包装以支持离线恢复。用户名等账户元数据仍然公开。

锁定或退出会移除数据密钥引用、完整包装资料、明文账号数据及解锁界面的组件状态。相同来源的标签页通过 BroadcastChannel 与持久锁定代次同步锁定，页面恢复可见及交互前再次检查。改密与恢复会锁定其他页面，发起页面保留新会话；通知接收方不再次注销共享 Cookie。所有已解锁页面共享最近活动时间，避免后台页在前台仍活跃时触发闲置锁定。页面进入后退缓存时清理本页，恢复后需重新解锁；无法持久保存代次时在失焦/恢复时保守锁定。

没有把明文或密钥放入 localStorage / IndexedDB。持久状态仅包含非敏感的锁定代次、活动时间及外观偏好。异步加密、认证及导出在继续操作前检查本页代次，迟到结果不重新打开已锁定界面。JavaScript 字符串和浏览器内存由运行时回收，不能保证强制物理清零。主动复制到系统剪贴板的内容不会自动清除。

## AI 数据流

聊天入口使用 `POST /api/ai/chat`。云端模型接收当前模式的多轮用户消息、每轮正在回答的字段及草稿序号、当前非密码草稿或查询条件、分类名称和结构化输出要求，返回完整的更新状态与简短回复。原 `POST /api/ai/parse` 保留供设置中的连接测试使用。两种接口都不提供写入工具。

录入草稿在客户端保留稳定标识；本地密码、手工编辑和已有账号的原始快照不因模型更正或重排而丢失。平台、登录标识和主体选择未完成时继续追问；已有账号目标不明确时由用户选择。用户在核对页确认或发送明确的“确认保存”后，才在独立副本中验证并提交整批变更，沿用过期编辑检查、加密写入和历史记录。模型不参与密码字段或已有记录内容的读取。

查询条件最终在浏览器内存中执行，命中数量、结果列表和下一步建议以真实数据为准；结果不发送给模型。补充条件保留前文，明确取消则删除对应筛选。记录和查询各自保留对话，打开查询详情会暂时隐藏助手，关闭详情恢复原对话。

密码的独立字段不会进入请求体。文字中的显式“密码／密钥”模式会被拒绝，但规则无法识别所有无标签秘密；不要把秘密混入云端自然语言。自然语言中的姓名、公司、账号或邮箱会随输入发送。

API Key 平时随账号库加密保存，调用时由浏览器解密后交给同源服务临时转发，服务端不将其落库或写入请求日志。模型供应商仍按自己的政策处理请求。

服务端按域名白名单验证 HTTPS 目标，并检查所有 DNS 结果是否为公网地址、固定实际连接解析结果、禁止自动跳转。返回体和 JSON 结构均限制大小，拒绝未声明的密码字段。账号登录链接在客户端保存/导入校验阶段限制为 HTTP(S)，并禁止 URL 内嵌用户名和密码。

本地助手不调用服务器或模型，支持逐项回答、常见字段更正、批量草稿序号和查询条件增减；复杂自然语言仍需云端模型或手工核对。单段对话限制 32 轮、24,000 字符，草稿最多 20 条。关闭、刷新或锁定后销毁对话；请求可停止，迟到的回复受会话代际和服务端会话复查保护。对话未写入账号库、日志或本地存储。可选 WebMCP 注册的 `start_account_capture` 只将文字放进聊天输入框，不保存、不调用云端；浏览器不支持时不会影响普通界面。

## 运行规模与限制

面向单人、单实例、同一台主机的本地 SQLite 磁盘。一次请求的密文上限约 8 MiB（Base64 编码长度）；历史较多时，可降低历史保留数量并导出备份。没有附件、团队权限、跨实例同步、自动填充、第三方平台自动改密或离线修改队列。

客户端加密可以保护数据库静态副本，但解锁设备、浏览器扩展或恶意修改的前端仍可能获取明文。必须信任提供 JavaScript 的主机及所使用设备。当前交付的自动化检查不是独立密码学或安全审计。
